## Интеграция

Игра находится в SNES_Template. main вызывает GameStart, затем GameUpdate
и GameDraw. Data/gameState.c обслуживает ввод и VBlank; переносимое ядро
не зависит от snes.h. Режимы заставки, меню, сцен, исследования и концовок
живут в едином Game, поэтому нет дублирующих состояние глобальных менеджеров.
Старые файлы intro/menu/over/musicManager сохранены как примеры и не линкуются.
Пользовательские SuperFamiconv/LibreSprite/эмуляторы в корне не изменены.

Сохранены все 177 страниц / 37 групп сцен, четыре локации, моральные решения,
три концовки, свет, масло, страх, преследование, журнал, три воспоминания,
колокола, серебро и обратные пути. JSON сценария перенесён без редактирования.
Скорость двухкадровой анимации шага теперь задаётся битом такта вместо деления;
появление текста использует отдельный счётчик с прежним интервалом шесть тиков.

## Память

| Объект | До | После |
|---|---:|---:|
| Карта текста в WRAM | 2048 B | 1792 B |
| Две таблицы HDMA | 350 B | 266 B |
| Состояние Game | 52 B | 52 B |
| Передача текстовой карты при изменении | 2048 B | 1792 B |

Буферы уменьшены суммарно на 340 байт. Для кеша видимости / неподвижных
спрайтов добавлено восемь байт: чистое уменьшение статики буферов и кеша — 332 байта.
Ещё три байта освобождены упрощением PAL-часов.
Счётчик появления текста занимает ранее свободный байт выравнивания Game.
Длина каждой реплики и таблицы округления UI хранятся в ROM, не WRAM.

Фактическая статика модулей игры — **2284 B** по dsb в сгенерированном ASM.
Лимит проверки — 3072 B. Это не сумма всей занятой памяти SNES: отдельно
остаются SDK, CPU-стек, OAM-буфер библиотеки, её runtime и память звукового CPU.
Не используем процент свободной RAM из суммы логических слотов WLA:
их адресные пространства частично отражают одну физическую память.

VRAM: максимум 26384 B реально загружаемых данных для текущего набора
ресурсов. Адреса PPU в video_layout.h указаны в **словах**, размеры — в байтах.
Максимальный фон — 310 тайлов / 9920 B; лимит слота — 512 тайлов / 16384 B.
Шрифт — 4176 B, OBJ — 8192 B, две карты по 2048 B. У текстовой карты остаётся
полный слот 32×32 в VRAM, но невидимые четыре строки не хранятся в WRAM
и не передаются DMA. Это не сокращение самой аппаратной карты PPU.

Три BRR-сэмпла занимают 1890 B из выделенного 4096 B региона. Память драйвера
SPC считается отдельно. Heap, float, runtime JSON и файлового ввода нет.
Графика, шрифт и текст читаются из ROM; одновременно загружается одна карта.

## Быстродействие

Убраны два программных деления из расчёта полосы фонаря; совпадение с прежней
геометрией проверяется для всех направлений, всех допустимых Y и граничных X.
Поиск предметов сначала отбрасывает удалённые точки. Статичная видимость и
OAM не пересчитываются без движения / смены света / UI или состояния актёров.
Неиспользуемые функции стрелкового прототипа удалены из линковки.
Часы PAL/NTSC и округление индикаторов не вызывают программное деление.
Heartbeat использует накопленный такт исследования, а не деление общего tick.

Локальный замер Snes9x: 600 эмулированных видеокадров, стартовая деревня,
обычный геймпад, читается счётчик последнего обработанного VBlank. RAM не
изменяется. Это частота обновления игрового цикла, **не** скорость хоста.

| Сценарий NTSC | Исходный перенос | Оптимизировано |
|---|---:|---:|
| Стоять без света | 296 | 592 |
| Стоять со светом | 198 | 594 |
| Поворачивать свет каждые 16 кадров | 178 | 522 |

В этих сценариях максимальный промежуток уменьшился с 4/5/6 до 3 VBlank.
PAL после оптимизации: 592/594/520 обновлений за 600 видеокадров. Реальная
SNES не проверена; переходы, текст, активная тень и другие сцены могут иметь
другой бюджет. Постоянные 60 FPS во всём прохождении не заявляются.
Исходные отчёты — build/profile-*.json; методика — tests/rom_profile.py.

## Надёжность сборки

Makefile явно перечисляет источники и исключает примеры / старый soundbank.
Заголовки инвалидируют стадию C → .ps. Компиляторный ASM не открывается заново
как самостоятельный исходник. Линкер работает с новым временным файлом;
после проверки размера, checksum и символов публикуются ROM и .sym.
build/link_manifest.json связывает их SHA-256; ROM-тесты отклоняют старые
символы. Неудачная линковка оставляет прежнюю ROM. Два теста воспроизводят
ошибочный линкер и дублирующийся объект. Ошибки инструментов не подавляются.

CI генерирует контент, запускает ядро / ASan / UBSan, проверяет бюджет памяти,
восемь прохождений ROM, профили PAL/NTSC и идентичность повторной сборки.
Затем создаёт архив исходников, ROM, сценария и PPU-кадров.
Стек и реальные аппаратные тайминги требуют отдельной проверки на железе.
